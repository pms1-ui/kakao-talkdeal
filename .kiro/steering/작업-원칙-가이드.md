# 카카오 톡딜 상세페이지 — 작업 원칙 & 디자이너 가이드 (전 회차 공통)

이 프로젝트는 회차별(예: 260806, 260903, 260911, 260918 ...)로 카카오 톡딜 묶음상품 상세페이지를 제작한다.
이 문서는 두 부분으로 나뉜다.
- **PART A. 작업 원칙 (에이전트용)** — 모든 회차에 예외 없이 적용되는 기술 규칙.
- **PART B. 디자이너 가이드 (사람용)** — 말로 시켜서 작업하는 방법을 쉽게 정리.

# PART A. 작업 원칙 (에이전트용)

## 회차 폴더 구조 (표준, 항상 이 5개 폴더 생성)

새 회차를 시작하면 `_작업소스/{회차}/` 안에 아래 5개 폴더가 항상 만들어진다.

| 폴더 | 내용 | 채우는 주체 | 서버 업로드 대상 |
|---|---|---|---|
| `기초데이터/` | 상품 엑셀(`상품데이터*.xlsx`), 행사내용 md | 디자이너(현업 정리) | ✕ |
| `누끼컷&사은품/` | 상품 누끼컷(바닥컷) + `사은품/` 하위폴더 | 디자이너(현업 수령) | ✕ (소스) |
| `메인&카드 캡처결과/` | 상단 `01~04.jpg` + `cards/{NN}.jpg` | 에이전트(capture 자동) | ○ card/ 및 상단 |
| `상세이미지/` | 피그마 품번별 상세 이미지 `{순서}_{품번}.jpg` | 디자이너(피그마) | ○ detail_image/ |
| `상품상세html/` | 엑셀기반 품번별 상세 html `{순서}_{품번}.html` | 에이전트(자동 생성) | ○ kakao_detail/ |

- 그 외 회차 폴더 직속 파일: `작업용.html`(원본), `main-image.jpg`(메인 배경), `kakao_final_{회차}.html/.txt`(카카오 붙여넣기 소스).
- **경로/폴더명 규칙 고정**: 스크립트가 이 폴더명을 하드코딩으로 참조하므로 폴더명을 바꾸면 스크립트가 깨진다.

### 스크립트 경로 매핑 (회차 스크립트 작성 시 기준)
- 엑셀 읽기: `_작업소스/{회차}/기초데이터/상품데이터*.xlsx`
- 카드/사은품 이미지 소스(작업용.html의 `src`): `누끼컷&사은품/` (사은품은 `누끼컷&사은품/사은품/`)
- 캡처 출력: `_작업소스/{회차}/메인&카드 캡처결과/` (+ `cards/`)
- 상세 html 출력: `_작업소스/{회차}/상품상세html/`
- 상세 이미지(피그마): `_작업소스/{회차}/상세이미지/` → 서버 `detail_image/`

### 서버(S3) 업로드 매핑
- `메인&카드 캡처결과/cards/{NN}.jpg` → `{서버폴더}/card/{NN}.jpg` (서버는 **card** 단수, 로컬은 **cards** 복수)
- `메인&카드 캡처결과/01~04.jpg` → `{서버폴더}/` 바로 밑
- `상세이미지/{순서}_{품번}.jpg` → `{서버폴더}/detail_image/`
- `상품상세html/{순서}_{품번}.html` → `{서버폴더}/kakao_detail/`
- 상세이미지·상세html·카드 링크의 파일명 규칙은 모두 **`{순서}_{품번}`** 로 통일한다.
- 서버 폴더명은 회차마다 다르다(예: 260911 = `2609_2_kakaotalk_deal`).

## 핵심 원칙: 생성과 수정을 분리한다

작업은 두 단계로 나뉘며, 절대 섞지 않는다.

### 1단계 — 최초 생성 (회차 시작 시 딱 1회)
- 엑셀 데이터를 기반으로 generate 스크립트를 실행해 `작업용.html`을 통째로 생성한다.
- 엑셀 파일과 generate 스크립트는 **회차마다 다르다** (파일명, 컬럼 구조, 로직이 바뀔 수 있음).
- 이 단계는 회차당 한 번만 수행한다.

### 2단계 — 부분 수정 (요청이 올 때마다)
- 사용자가 "구성 N번 상품명/가격/이미지/컬러 수정" 같은 개별 수정을 요청하면:
  - **generate 스크립트를 절대 다시 실행하지 않는다.** (재실행하면 그동안의 수동 수정이 전부 사라짐)
  - `작업용.html`을 **직접 편집**한다.
  - 요청받은 그 부분(그 카드)만 수정한다. 다른 카드는 건드리지 않는다.
  - 수정한 카드를 포함해 캡쳐 스크립트로 `_작업소스/{회차}/메인&카드 캡처결과/cards/*.jpg`를 재생성한다.
  - 로컬 확인용 프리뷰(`미리보기/{회차}_로컬확인.html`)를 열어 확인한다.

## 하지 말아야 할 것

- ❌ 부분 수정 요청에 generate 스크립트(엑셀 재생성)를 다시 돌리기 → 수동 수정분 유실
- ❌ 특정 카드 예외처리 로직을 generate 스크립트에 박아넣기 (예: "구성4는 NEW 빼기")
  → 엑셀·스크립트·수동수정이 뒤엉켜 source of truth가 불명확해짐
  → 예외는 스크립트가 아니라 `작업용.html`에서 직접 처리한다
- ❌ 엑셀을 기준으로 "다른 카드도 맞춰서" 함께 수정하기 → 요청 범위를 넘지 말 것

## Source of Truth

- 최초 생성 직후: 엑셀 = 원본
- 부분 수정이 시작된 이후: **`작업용.html`이 최신 원본**이다.
  수동 수정분은 엑셀에 없을 수 있으며, 이것이 정상이다.

## 수정 시 주의 (중복 텍스트)

- 상품명·가격 텍스트가 여러 카드에 중복될 수 있다.
- 단순 문자열 치환은 엉뚱한 카드를 바꿀 위험이 있으므로,
  반드시 **구성 번호("구성 NN") 위치를 기준으로 해당 카드 블록 안에서만** 수정한다.

## 표준 파이프라인 요약

```
[기초데이터/엑셀] --(generate, 회차당 1회)--> [_작업소스/{회차}/작업용.html] --(capture)--> [_작업소스/{회차}/메인&카드 캡처결과/cards/*.jpg] --(S3 업로드)--> 실서비스/미리보기
                                                        ▲
                                           부분 수정은 여기를 직접 편집
```

## 전체 한 장 캡처 (맨위~맨아래 세로 긴 이미지, 확인용)

회차 페이지 전체(상단 로고바+메인비주얼 → 구성 01~끝까지)를 **한 장의 세로 긴 JPG**로 뽑아
루트 폴더 `{회차}_전체.jpg`에 저장한다. 디자이너가 "전체 한 장으로 캡처해줘" 할 때 쓴다.

- **표준 스크립트: `_스크립트/capture_full_stitch.mjs`** (회차를 인자로 받음)
  ```bash
  node "_스크립트/capture_full_stitch.mjs" 260911   # 회차 생략 시 기본 260911
  ```
- **끊김 방지 원리**: 긴 페이지를 `fullPage`로 통째 찍으면 아래가 잘리므로,
  1500px(CSS) 조각으로 나눠 `clip`으로 각각 캡처 → sharp로 세로 이어붙인다. 2x 배율.
- **자동 검증 2종**(반드시 통과 확인):
  1. 이미지 로드 검증 — 깨진 이미지 목록 출력(0개여야 정상)
  2. 높이 검증 — `페이지높이×2 == 결과 이미지 높이`(불일치 시 잘림 경고)
- 검증 후 육안 확인이 필요하면 결과 JPG에서 상단/중간/하단 3구간을 잘라 확인한다.
- **`{회차}_전체.jpg`는 확인용 산출물**이라 git·S3에 올리지 않는다(.gitignore 제외). 실배포는 `cards/`.

## 배포 전 필수 체크리스트 (S3 업로드/커밋 전에 항상 확인)

업로드하거나 커밋하기 전에 **반드시 아래를 확인한다.** 특히 상품이 추가/삭제된 회차에서 누락이 잦다.

1. **상품 수 일치 확인** — 아래가 전부 같은 개수인지 대조한다.
   - 엑셀 구성 수 = `작업용.html`의 "구성 NN" 수 = `cards/*.jpg` 수
     = `상품상세html/*.html` 수 = `상세이미지/*.jpg` 수
     = `kakao_final_{회차}.txt`/`.html`의 카드 수
     = `미리보기/{회차}_카카오톡딜.html`·`{회차}_로컬확인.html`의 카드 수
     = `index.html`의 해당 회차 "N개 구성" 표기
2. **미리보기 갱신 확인** — 카드가 바뀌었으면 아래 3개가 **모두** 새 개수로 갱신됐는지 본다.
   - `미리보기/{회차}_로컬확인.html` (로컬 이미지 참조)
   - `미리보기/{회차}_카카오톡딜.html` (S3 참조, **네틀리파이 배포 대상**)
   - `index.html`의 해당 회차 카드 메타("N회차 · N개 구성")
3. **카드 링크 ↔ 상세html 파일명 일치** — `card/{NN}` ↔ `kakao_detail/{순서}_{품번}.html` 매핑이 어긋나지 않는지 확인(404 방지).
4. 위 3가지는 `gen_kakao_final` 스크립트가 로컬확인·카카오톡딜 미리보기를 함께 생성하므로, 카드 재생성 시 이 스크립트를 돌려 자동 동기화한다. `index.html`은 수동 갱신 대상이므로 잊지 말 것.

## 배포 (S3 업로드)

- 부분 수정 후 실제 반영에 필요한 것은 보통 **`_작업소스/{회차}/메인&카드 캡처결과/cards/` 폴더(카드 이미지)뿐**이다.
- 상세 HTML/상세 이미지는 내용 변경이 없으면 다시 올리지 않는다.
- 상세 이미지(`detail_image/`)는 기존 S3 파일을 재사용한다 (새로 올리지 않음).

## 품절임박 딱지 (재사용 표준)

품절 임박 상품 카드에 붙이는 빨간 아웃라인 딱지. 260903 회차에서 처음 도입.

### 표시 규칙
- **NEW 딱지가 있는 카드** → 품절임박은 NEW **아래**에 배치.
- **NEW 딱지가 없는 카드** → NEW 자리인 **좌상단(top:10px; left:10px)**에 배치.
- 대상은 반드시 **화면의 "구성 NN" 텍스트 기준**으로 찾는다.
  (상품이미지 파일명 앞 숫자와 구성번호가 다를 수 있음 — 카드 삭제/재번호된 회차 주의)

### 스타일 스펙 (그대로 복붙해서 재현)
- 배경: 반투명 흰색 `rgba(255,255,255,0.6)` (거의 투명, 아웃라인 스타일)
- 테두리: `1.9px solid #FF3B30` (빨강)
- 글자색: `#FF3B30` (빨강)
- 폰트: `Pretendard, sans-serif`, `font-size:17.5px`, `font-weight:800`
- 안쪽 여백: `padding:5px 12.5px`, 모서리 `border-radius:8.75px`
- 불꽃 아이콘: `누끼컷&사은품/fire.png` (검은 불꽃 원본을 빨강+투명 변환한 것), `width/height 16.25px`
  - 원본 검은 아이콘: `_작업소스/공용에셋/fire.png`
  - 빨강 변환본: `_작업소스/공용에셋/fire_red.png` (캡처용으로 회차 `누끼컷&사은품/fire.png`에 복사해 사용)
- 아이콘과 글자 간격: `gap:5px`, 세로 정렬 `align-items:center`
- 레이어: `position:absolute; z-index:3`

### HTML 스니펫
```html
<div style="position:absolute; top:10px; left:10px; background:rgba(255,255,255,0.6); border:1.9px solid #FF3B30; color:#FF3B30; font-family:Pretendard,sans-serif; font-size:17.5px; font-weight:800; padding:5px 12.5px; border-radius:8.75px; z-index:3; display:flex; align-items:center; gap:5px;"><img src="누끼컷&사은품/fire.png" style="width:16.25px; height:16.25px; display:block; flex-shrink:0; object-fit:contain;">품절임박</div>
```

> 삽입 위치: 각 카드의 이미지 영역(`position:relative`인 div) 안, 그 카드의 상품 `<img>` 바로 앞.
> 여러 카드에 중복 문자열이 있으므로, 삽입 앵커는 각 카드의 **고유 상품 누끼컷 파일명**을 사용한다.
> 삽입 후 반드시 capture 스크립트로 재캡처 → 대상 카드 이미지에 딱지가 구워진다.

## 부분 수정 기법 모음 (자주 나오는 패턴)

### 컬러칩 HEX 변경 — 구성번호/앵커 기준 필수
- 컬러칩 hex는 여러 카드에 중복될 수 있다. 전역 치환 전 반드시 **등장 횟수를 먼저 센다**(`grep -o`).
- 등장 횟수 == 요청 대상 카드 수이면 전역 치환 안전. 그 외에는 **해당 카드 블록 안에서만** 교체
  (그 카드의 고유 상품 누끼컷 파일명 + 인접 칩 조합을 앵커로 묶어서 치환).
- 새 hex가 밝은 색(연회색/연베이지/연블루 등)이면 흰 카드에서 안 보이므로 `border:1px solid #ddd` 추가.

### 사은품: 한 카드에 여러 컬러 나란히
- "컬러 모두 노출" 요청 시, 사은품 카드의 이미지 영역을 `display:flex; gap; justify-content:flex-end`로 두고 img 여러 개 배치.
- 각 이미지 폭은 개수에 맞춰 축소(2개면 약 155~170px). 흰 배경 누끼는 `trim()`으로 여백 제거 후 사용.

### 모델컷/사진 배경 제거(누끼)
- 배경이 밝고 균일하면 flood-fill 방식으로 자동 누끼 가능.
  - 테두리에서 시작해 "밝고 무채색(THRESH~236, max-min≤18)" 픽셀만 투명화 → 내부 밝은 옷/얼굴 보존.
- 결과는 `*_누끼.png`로 저장하고 원본은 남긴다. 경계 품질이 완벽하진 않으니 결과 확인 후 사용.

### 사은품 유의사항(footer) 박스 좌우 꽉 채우기
- 사은품 컨테이너는 `padding:60px 24px 0`(좌우 24px 여백)이라, footer가 `width:100%`면 좌우에 회색 배경이 남아 어색하다.
- 해결: footer를 `align-self:stretch; width:890px; margin:32px -24px 0`로 두어 컨테이너 좌우 padding을 음수마진으로 상쇄 → 890px 꽉 채움.

### 가격 노출 변형 (구성별)
- "최종가 없이 톡딜가만" 같은 요청은 해당 구성 카드의 가격 블록에서 최종가 `<div>`를 제거하고, 톡딜가를 강조색으로 남긴다.
- 할인율 숫자는 요청값으로 직접 교체(자동계산과 다를 수 있음 — 요청값 우선).

### 브랜드 표기 위치 주의
- "행사명/브랜드" 수정 요청은 **상단바(top-bar)** 를 의미하는 경우가 많다(로고 나란히 있는 남색 바).
  메인 비주얼 안쪽 타이틀과 혼동 말 것. 어느 위치인지 애매하면 캡처 이미지의 해당 영역을 먼저 확인한다.
- 로고 파일이 없는 브랜드는 텍스트로 표기(예: 미소데이즈).

# PART B. 디자이너 가이드 (사람용)

> 에이전트에게 말로 시켜서 작업하는 방법을 쉽게 정리한 문서예요.
> 기술적인 건 에이전트가 다 할거니, 명령만 하시면 돼요.

## 먼저, 이게 무슨 일이냐면

카카오 톡딜에 올릴 **상품 모아보기 페이지**를 만드는 일이에요.

- 상품이 카드처럼 쭉 나열되고, 카드를 누르면 그 상품 상세 화면으로 넘어가요.
- 이걸 **회차별로** 만들어요. 회차는 그냥 진행 날짜예요.
  예를 들어 `260918`은 2026년 9월 18일에 진행하는 묶음이에요.

디자이너가 할 일은 딱 하나예요.
**"뭘 어떻게 고쳐줘"** 하고 에이전트한테 말로 시키는 거예요. 나머지 기술적인 건 에이전트가 처리해요.

## 0단계. 시작 전 준비 작업 (현업 파일 정리 + 사진 넣기)

에이전트한테 "만들어줘" 하기 전에, 디자이너가 먼저 해두는 밑작업이에요. 크게 두 가지예요.

### (1) 현업이 준 엑셀을 "표 형태"로 정리하기

- **맨 첫 줄(첫 행)** 에는 **필드명(제목)만** 쭉 넣어요.
  예: `순서 | 년도 | 시즌 | 모델번호 | 모델_컬러 | 컬러코드 | 품목명 | 택가 | 톡딜가 | 혜택가 | 최종할인율`
- **그 아래 줄부터** 실제 상품 데이터가 한 줄에 하나씩 쫙 깔리게 해요.
- 정리한 엑셀은 `_작업소스/{회차}/기초데이터/` 폴더에 넣어둬요.

> 표 정리도 어려우면 받은 파일을 주면서 "이거 첫 줄에 필드명, 아래에 데이터로 정리해줘" 라고 에이전트한테 시켜도 돼요.

### (2) 사진을 폴더 규칙에 맞게 넣어두기

**① 상품 누끼컷 (현업한테 받은 것)** — 카드에 보이는 상품 바닥컷
- 넣는 곳: `_작업소스/{회차}/누끼컷&사은품/`
- 이름 규칙: `순서.모델코드_컬러.png` (예: `12.OD263ILS09_GRY.png`)
- 뒷면/착장 등 한 카드에 2장이면 두 번째는 `-1` 붙임 (예: `12-1.OD263ILS09_GRY.png`)
- 사은품 누끼컷은 `_작업소스/{회차}/누끼컷&사은품/사은품/` 안에

**② 상품 상세 이미지 (피그마에서 작업한 것)** — 카드 눌렀을 때 뜨는 긴 상세 화면
- 넣는 곳: `_작업소스/{회차}/상세이미지/`
- 이름 규칙: `순서_모델코드.jpg` (예: `67_OD243BPT08.jpg`)
  - ⚠️ 누끼컷과 규칙이 조금 달라요. 누끼컷은 `12.모델_컬러`, 상세는 `67_모델코드` (점이 아니라 밑줄, 컬러 없음)
- 이 상세 이미지는 최종적으로 **서버의 `detail_image/` 폴더**로 올라가요.

> 정리하면: **누끼컷 = 카드용(누끼컷&사은품 폴더), 상세 = 피그마 작업물(상세이미지 폴더 → 서버 detail_image).**

## 작업은 딱 두 종류뿐이에요

### 종류 1. 새 회차를 처음 만들 때 (회차당 딱 한 번)

> "260918 회차 새로 시작할게. 엑셀이랑 누끼컷 준비됐어. 페이지 만들어줘."

그럼 에이전트가 엑셀을 읽어서 카드들을 **한꺼번에 자동으로** 쫙 만들어요. **회차당 딱 한 번만** 하는 작업이에요.

### 종류 2. 이미 만든 걸 고칠 때 (제일 자주 하는 일)

> "구성 12번 상품명을 이걸로 바꿔줘" / "구성 30번 가격 89,000원으로 고쳐줘" / "구성 4번은 NEW 딱지 빼줘"

이때는 처음부터 다시 만드는 게 아니라, **그 카드 하나만 콕 집어서** 고쳐요.

## ⚠️ 여기가 제일 중요해요 (사고 안 나려면)

**한번 만든 다음부터는, 엑셀로 다시 만들면 안 돼요.**

- 처음 엑셀로 만든 뒤에, 우리는 손으로 이것저것 고쳐왔어요.
- **엑셀로 처음부터 다시 만들어버리면, 그동안 손으로 고친 게 전부 사라져요.**

> **처음 만들 때만 엑셀. 그 다음부터는 손으로 그 카드만 고친다.**

그냥 **"구성 몇 번을 이렇게 고쳐줘"** 라고만 말하면, 에이전트가 알아서 엑셀 안 건드리고 그 카드만 고쳐요.

## 폴더는 이렇게 생겼어요

```
8 (카카오 톡딜)/
│
├── _작업소스/                     ← 여기가 작업 재료 창고
│   ├── 공용에셋/                  로고·배경 (회차 상관없이 공용)
│   │
│   ├── 260918/                   ← 회차 폴더 (회차 하나당 폴더 하나)
│   │   ├── 기초데이터/            엑셀·행사내용 (엑셀은 처음 만들 때만 씀)
│   │   ├── 누끼컷&사은품/         ★ 현업이 준 상품 누끼컷(바닥컷) 넣는 곳
│   │   │   └── 사은품/            사은품 누끼컷은 여기
│   │   ├── 메인&카드 캡처결과/    ★ 에이전트가 캡처한 결과 (상단 01~04 + 카드)
│   │   │   └── cards/             완성된 카드 이미지(01.jpg~) → 서버에 올릴 것
│   │   ├── 상세이미지/            ★ 피그마 상세 작업물 → 서버 detail_image/로 업로드
│   │   ├── 상품상세html/          엑셀기반 품번별 상세 html → 서버에 업로드
│   │   ├── 작업용.html            ★ 진짜 원본. 수정은 전부 여기서 (에이전트가 함)
│   │   └── main-image.jpg         메인 비주얼 배경
│   │
│   └── (다음 회차)/               다음 회차는 이렇게 새 폴더로
│
├── 미리보기/                      ← 눈으로 확인하는 화면
│   ├── {회차}_로컬확인.html       내 컴퓨터 이미지로 미리 확인 (인터넷 없어도 됨)
│   └── {회차}_카카오톡딜.html     서버 이미지로 확인 (네틀리파이에 뜨는 것)
│
├── _스크립트/                     에이전트가 쓰는 자동화 도구 (디자이너는 안 건드림)
│
└── .kiro/steering/작업-원칙-가이드.md  ← 지금 읽는 이 문서
```

새 회차를 시작하면 회차 폴더 안에 아래 5개 폴더가 항상 만들어져요.

| 폴더 | 무엇을 넣나 | 누가 채우나 |
|---|---|---|
| `기초데이터/` | 상품 엑셀, 행사내용 메모 | 디자이너 (현업 파일 정리) |
| `누끼컷&사은품/` | 상품 누끼컷(바닥컷) + `사은품/` 하위폴더 | 디자이너 (현업한테 받은 것) |
| `메인&카드 캡처결과/` | 상단 4장 + `cards/` (카드 이미지) | 에이전트 (캡처 자동) |
| `상세이미지/` | 피그마에서 만든 품번별 상세 이미지 | 디자이너 (피그마 작업물) |
| `상품상세html/` | 엑셀 기반으로 자동 생성되는 품번별 html | 에이전트 (자동 생성) |

> ⚠️ 폴더 이름은 마음대로 바꾸지 마세요. 회차 폴더(`260918` 같은 숫자)와 위 5개 폴더 이름이 바뀌면 스크립트·서버 주소랑 안 맞아서 화면이 깨져요.

## 받은 파일은 어디에 넣나요

| 받은 것 | 넣는 곳 | 파일 이름 규칙 |
|---|---|---|
| 상품 누끼컷 (현업) | `_작업소스/{회차}/누끼컷&사은품/` | `순서.모델코드_컬러.png` (예: `12.OD263ILS09_GRY.png`) |
| 상품 뒷면/착장 사진 | `_작업소스/{회차}/누끼컷&사은품/` | 같은 번호에 `-1`을 붙임 (예: `12-1.OD263ILS09_GRY.png`) |
| 사은품 누끼컷 | `_작업소스/{회차}/누끼컷&사은품/사은품/` | 그대로 |
| 상품 상세 이미지 (피그마) | `_작업소스/{회차}/상세이미지/` → 서버 `detail_image/` | `순서_모델코드.jpg` (예: `67_OD243BPT08.jpg`) |
| 상품 목록 엑셀 | `_작업소스/{회차}/기초데이터/` | 첫 줄=필드명, 아래=데이터 |

> 회차 폴더를 아직 안 만들었으면 "260918 회차 폴더 만들어줘"라고 하면 에이전트가 만들어줘요.

## 반영은 어떻게 되나요 (재료 → 화면까지)

```
① 누끼컷 + 엑셀 넣기            ← 디자이너가 함
        ▼
② 작업용.html 만들기/고치기      ← 에이전트가 함 (자동)
        ▼
③ 카드 이미지(jpg)로 뽑기        ← 에이전트가 함 (자동) → 메인&카드 캡처결과/cards/
        ▼
④ 미리보기로 눈 확인            ← 디자이너가 함
        ▼
⑤ 서버(S3)에 올리기            ← 이 단계까지 하면 카카오에 반영
```

디자이너는 **①(재료 넣기) → ④(확인) → ⑤(올리기)** 만 하면 되고, 가운데는 "만들어줘 / 고쳐줘" 한마디면 에이전트가 처리해요.

## 서버 어디에 올리나요

완성된 카드 이미지(`메인&카드 캡처결과/cards/` 안의 jpg들)를 서버에 올려요.

- **서버(S3) 위치** (회차 서버폴더 예: 260911 = `2609_2_kakaotalk_deal`)
  ```
  aws-childy-image 버킷 / img/outdoor2026/promotion/{회차 서버폴더}/card/
  ```
- **인터넷 주소로는**
  ```
  https://img.childy.kr/img/outdoor2026/promotion/2609_2_kakaotalk_deal/card/01.jpg
  ```
- 회차마다 서버 폴더 이름이 달라요. 어느 폴더에 올릴지는 에이전트한테 물어보면 알려줘요.

서버 폴더는 이렇게 나뉘어요.
- (폴더 바로 밑) — 상단 공통 이미지 `01_main_visual.jpg` `02_kakao_channel.jpg` `03_benefits.jpg` `04_tokdeal_benefits.jpg`
- `card/` — 카드 썸네일 이미지 (`01.jpg` ~) ※ 폴더명이 **card**(단수)
- `detail_image/` — 카드 눌렀을 때 뜨는 상세 이미지 (`순서_모델코드.jpg`, 피그마 작업물)
- `kakao_detail/` — 카드 눌렀을 때 열리는 상세 페이지 html

무엇을 올리냐면 상황에 따라 달라요. **헷갈리면 에이전트한테 "이번에 올릴 이미지 목록 알려줘" 하면 딱 집어줘요.**
- **새 회차 처음**: 상단 4장 + `card/` + `detail_image/` + `kakao_detail/` 전부.
- **카드만 고쳤을 때**: 바뀐 카드 이미지만 `card/`.
- **상단(메인/사은품/톡딜혜택)만 고쳤을 때**: 바뀐 상단 이미지만(예: `03_benefits.jpg`) 폴더 바로 밑에.
- **상세 이미지만 고쳤을 때**: 바뀐 상세 이미지만 `detail_image/`.
- 내용이 안 바뀐 건 다시 안 올려도 돼요.

### 파일질라(FileZilla)로 올리는 순서

1. **파일질라를 켜고 서버에 접속해요.** (호스트/사용자명/비밀번호/포트는 회사에서 받은 정보로 저장해두면 다음엔 고르기만)
2. **화면은 왼쪽 = 내 컴퓨터, 오른쪽 = 서버.**
3. **왼쪽(내 컴퓨터)** 에서 이동:
   ```
   _작업소스/{회차}/메인&카드 캡처결과/cards/
   ```
   > 참고: 내 컴퓨터 폴더는 `cards`(복수)지만, 올리는 서버 폴더는 `card`(단수)예요.
4. **오른쪽(서버)** 에서 올릴 폴더로 이동 (회차 서버폴더 예: `2609_2_kakaotalk_deal`):
   - 카드: `img/outdoor2026/promotion/2609_2_kakaotalk_deal/card/`
   - 상세 이미지: `.../detail_image/`
   - 상단 공통 이미지: `.../2609_2_kakaotalk_deal/` (바로 밑)
5. **왼쪽에서 오른쪽으로 드래그.** 카드 몇 장만 고쳤으면 그 파일만.
6. **"덮어쓸까요?" → [덮어쓰기]** 선택. ("이후 항목에도 적용" 체크 켜면 한 번에)
7. **아래쪽 전송 목록에 실패(빨간색) 없는지 확인.**

올린 뒤: 예전 이미지가 잠깐 보이면 **세게 새로고침(Cmd+Shift+R)** 하거나 조금 기다리면 새 걸로 바뀌어요.

> ⚠️ 오른쪽(서버)에서 폴더를 지우거나 이름을 바꾸지 마세요. 올리기(드래그)만 해요.

## 고쳐달라고 할 때 요령

**"구성 번호"를 꼭 같이 말해주세요.**
- ⭕ "**구성 30번** 가격을 79,000원으로 바꿔줘"
- ❌ "가격 79,000원짜리를 89,000원으로 바꿔줘"

같은 상품명/가격이 여러 카드에 겹칠 수 있어서, 번호 없이 말하면 엉뚱한 카드가 바뀔 수 있어요. **번호로 콕 집어주면** 그 카드만 정확히 고쳐요. 그리고 **말한 것만 고쳐요.**

## ✅ 올리기 전에 꼭 체크 (상품 수가 바뀐 회차는 특히)

올리기 전에 에이전트한테 **"올리기 전에 상품 수랑 미리보기 다 맞는지 확인해줘"** 라고 한 번 시키면 돼요.
1. **상품 수가 다 맞나요?** — 카드 개수, 상세 개수, 미리보기 개수, 메인 목록(`index.html`)의 "N개 구성"이 전부 같은 수인지.
2. **미리보기가 새 걸로 바뀌었나요?** — `{회차}_로컬확인.html`, `{회차}_카카오톡딜.html`(네틀리파이), `index.html` 세 개 모두.
3. **카드 눌렀을 때 엉뚱한 상세로 안 가나요?**

> 특히 2번을 자주 놓쳐요. 카드만 새로 만들고 "인터넷 미리보기"를 안 바꾸면 네틀리파이엔 옛날 개수가 그대로 떠요.

## 그래서, 딱 이것만 기억하세요

1. **준비/재료 넣기** — 엑셀은 `기초데이터/`, 상품 누끼컷은 `누끼컷&사은품/`, 피그마 상세는 `상세이미지/`.
2. **만들기 / 고치기** — 에이전트한테 말로. 새 회차 "만들어줘", 수정은 "구성 몇 번을 이렇게"(번호 꼭!).
3. **확인** — `미리보기/` 화면을 브라우저로 열어 눈으로.
4. **올리기** — 파일질라로 `메인&카드 캡처결과/cards/` → 서버 `.../card/` 드래그(덮어쓰기).

가운데 기술적인 건 다 에이전트가 해요.
